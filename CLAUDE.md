# Deep Line: notes for working on this repo

Android fishing collection game (Kotlin + Jetpack Compose) with a Ktor battle server.
Modules: `core` (pure-Kotlin rules, battles, bot, online protocol), `server` (Ktor WebSockets),
`app` (Compose UI). See README.md for the rules and layout.

## Rules

- **Keep the in-app tour up to date.** Every new player-facing feature (screen, mode, rule,
  upgrade, item) needs a step, or an updated step, in
  `app/src/main/kotlin/com/deepline/fishing/ui/tour/Tour.kt`. When you add steps, bump
  `Tour.VERSION` and set `sinceVersion = Tour.VERSION` on them: returning players then get a short
  "What's new" tour of just those steps. Point steps at UI with `Modifier.tourTarget(...)`.
  `TourContentTest` fails when a screen, battle mode or rope upgrade isn't covered; extend it
  when you add new kinds of features.
- **Fishing secrets are hidden mechanics: never reveal them in the tour** (`TourContentTest`
  checks for giveaways, including every secret's title). To add one: in `core/.../Secrets.kt`
  add its id to `Secrets` (and `Secrets.all`), its trigger and bonus to `SecretRules.bonuses`,
  and its discovery reward to `SecretRewards`; then describe it in
  `app/.../ui/secrets/FishingSecrets.kt`. Bonuses are part of `CastResult.totalPoints`, so they
  count in battles too and the online server recomputes them: if a secret needs a new fact about
  the cast, add it to `CastResult` and `CastDto`, and validate it in `CastValidation`. A secret
  is explained the first time it happens (with "show again next time?") and listed in the Dex's
  Secrets section, which only appears once one has been found.
- **Species**: 16 hand-made ones and the legendary Deep Sovereign in `FishSpecies.kt`, the rest
  generated by `SpeciesGenerator` from a fixed seed. Ids are saved in players' logs: changing the
  generator's word lists, counts, seed, or the hand-made names it avoids would rename species
  (the generator tests pin the names, so a test fails if that happens). `lastBumpOnly` species can't be caught on the ascent and the server
  checks it.
- **Cosmetics (skins) must never give a gameplay advantage**: same hook size and hitbox, nothing
  that lights up dark water or changes what the player can see. They're unlocked by legendary
  secrets (`Cosmetic.unlockedBy`, a full set of 5 slots each), drawn in 3D by `SceneBuilder`
  (and in 2D by `SkinArt.kt`) before the darkness layer and only around the player's own gear, and chosen in the Dex's Skins
  section. Titles (`CosmeticSlot.TITLE`) are text shown under the player's name; the server only
  relays titles that match a cosmetic.
- **Skins section** (always visible: everyone can customise a boat). Tapping the boat on the Fish
  tab opens it. It holds:
  - **Your boat**: a hand-made `BoatDesign` (`core/.../BoatDesign.kt`), edited in
    `ui/boat/BoatEditorScreen`. Options unlock per `BoatParts` (free, bought once with points from
    the balance, or by progress: species caught, a fish from a zone, milestones claimed); all its
    numbers are in that table and the default design must stay fully free. `Progression`
    enforces it (`setBoatDesign` refuses locked options). Wearing the custom boat and a boat
    cosmetic are mutually exclusive (`equipCustomBoat` / `equipSkin`). Build `Skins` with
    `vm.skins`, never `Skins.of(equippedSkins)` alone.
  - **Shop boats** (`PremiumSkins`, sold on the Shop's Style page): premade boats; buying one
    unlocks every option it uses. `PartRequirement.PremiumOnly` options (shop paints, emblems,
    prints) are bought in the Shop; `ClubOnly` ones (Aurora) last while a Captain's Club member.
    Season boats are PremiumSkins too, granted by the season pass, never sold alone.
  - **Title badge and Dex cards** (`core/.../Showcase.kt`): `TitleFrame` (relayed online, the
    server only passes known names) and `CardStyle` (a frame and sheen on caught cards, never
    the fish or the water). Owned shop gear has its own group; legendary sets stay secret-only.
  - **Atmosphere**: `Atmosphere.NIGHTMARE` unlocks when a cast reaches
    `DepthZone.ABYSS.minDepth` (`Progression.applyCast`). It only changes the mood: the player
    must see exactly as much as in FAMILY.
  - The 2D boat (classic, skins and designs) is drawn by `drawBoat` in `BoatArt.kt`; every
    `HullPattern`, `SailStyle`, `FlagStyle` and `Emblem` must also be drawn in 3D.
- **Navigation**: four bottom tabs (`MainTab`: Fish = `Screen.HOME`, Dex, Shop = `Screen.SHOP`,
  Battle = `Screen.BATTLE_SETUP`) in `MainScaffold`; the Shop's pages are `ShopPage` (tour steps
  pick one with `shopPage`); everything else is a full screen pushed on top (no
  bar). Tab screens use `TabScreen` (title + actions), pushed ones `SubScreen` (back button). Back
  from a tab goes to Fish. Tests tap tabs by tag (`tab_fish`, `tab_dex`...). Icons are drawn in
  code in `GameIcons` (no icon library).
- **Dex**: every species picture goes through `ui/dex/FishPortrait` (`DexState` UNKNOWN / SEEN /
  CAUGHT from `Progression.dexState`). "Seen" is recorded by `CastSession` (see
  `GameConfig.SEEN_DISTANCE_M`) and is a log feature only: never scored or sent online. Locked
  secret cards show only number, tier (`Secrets.tierOf`) and reward, and locked skins only their
  slot: never names that hint at a secret.
- **3D renderer** (`ui/render3d/`): pure-Kotlin meshes (`FishModels`, `PropModels`) and a
  `SceneBuilder` that turns a `CastSession` into a `Frame` (a list of draw items) on the main
  thread; `gl/GlBackend` only executes frames, on the GL thread (`Scene3d` for casts, `OffscreenGl`
  for Dex portraits and the skins preview). Shaders are GLSL ES 3.00 in `app/src/main/assets/shaders`
  (`#include` is resolved by `ShaderSource`). Rules:
  - The camera maps the play plane (z = 0) exactly like the 2D view (`Camera3d`, tested): never
    move gameplay objects off it, and keep fish meshes in the 2D art's unit space so the drawn
    head matches the hitbox (`Render3dTest`).
  - Darkness is a screen-space overlay with the same falloff as 2D, drawn after the scene and
    skins; only lures (and the Lantern glow) are drawn after it. Decor stays far behind the play
    plane and fogged so it never looks like an obstacle.
  - The 2D renderer is the fallback (no GLES 3, Robolectric, or any GL failure sets
    `Render3d.failed`), and the 2D overlay (`drawCastOverlay`: labels, aim, flashes) is drawn on top
    of the 3D view. Keep both working: the UI tests only see the 2D one.
  - There's no emulator here: check rendering with the WebGL preview. Run
    `./gradlew :app:testDebugUnitTest --tests '*Render3dExportTest'` then
    `node tools/render3d-preview/render.cjs` (PNGs in `app/build/render3d/`). It mirrors
    `GlBackend`'s draw rules: change both together.
  - GL keeps uniforms per program: per-item uniforms must be in `GlBackend.DEFAULTS` (and the
    preview's `defaults`) so one item's values never leak into the next.
  - The boat, rod and line are one design in 3D and 2D: the hull's lines (`PropModels.sheerAt`,
    `keelAt`, `halfBeamAt`) match `hullPath`/`sheer2d` in `BoatArt.kt`; the rod (`rodItem`) matches
    `drawBoatAndRod` (graphite blank, cork grip, reel, guides); classic colours are in `BoatLook`.
    Change both renderers together. The hull's near side sits in front of the play plane, so a
    translucent `waterSkirt` and the hull's depth fade keep it reading as under water.
  - Lighting follows the usual stylised recipe: a cel ramp with cool shadows, a stepped specular,
    rim light, hemispheric ambient and analytic AO in the material functions (no textures).
- **Colours** come from `ui/ColorScript.kt`, shared by the 3D renderer, the 2D fallback and the
  Dex: the water, light and specks by depth (bright and warm in the shallows, then cooler, darker
  and less saturated, near-black with sparse red/cyan glows in the abyss), and `FishLooks` for
  every species (zone palettes, designed looks for the hand-made ones, and "menace" features by
  depth: round, big-eyed, blushing fish near the surface; spines, teeth, glowing/slit eyes and
  photophores deeper). Don't hard-code fish or water colours elsewhere. Glowing eyes and
  photophores are drawn before the darkness (only lures shine through it), so deep fish are no
  easier to see.
- **Menu themes** (`core/.../Themes.kt`, `ui/theme/`): the menus sit on a sea scene
  (`ThemeBackdrop`, drawn in the draw phase only, never behind a cast) in the theme's
  `MenuPalette`, which also builds the Material colour scheme (`colorSchemeOf` in `Theme.kt`).
  Lagoon is the default and free; every theme has a day and a night version (`NightMode`: Day by
  default, Night, or like the phone); shop themes cost more the richer their scene (`tier`), and
  Aurora is a Club perk. Roles are the same in every theme: `primary` for actions,
  `secondaryContainer` for selection, `secondary` for highlighted text, gold for rewards (use
  `rewardTextColor()` for gold text, `zoneTextColor()` for a zone's name: plain `SparkleGold` and
  `zoneColor` are too pale on light cards). Cards are glass (`surfaceContainer*` roles); text keeps
  4.5:1 contrast on cards and on the scene, so check new screens in a light and a dark theme
  (`ThemesUiTest` screenshots every theme). Don't hard-code UI colours: take them from
  `MaterialTheme.colorScheme` or `LocalMenuPalette`. Themes never change a cast's water.
- **Atmosphere** (`Atmosphere.NIGHTMARE`, a cosmetic): changes colours, fish menace and decor in
  the deep only; the lit radius and what's visible stay exactly the same (darkness alpha is
  unchanged, only its tint).
- **Difficulty and economy are tuned by simulation**, so re-run and re-tune when you change
  scoring, the water or prices:
  - `DifficultyTest` (core): a human-like `GoodPlayer` (sees only the screen or the lit circle,
    0.25 s reactions, full rope) must reach the bottom in about a third of casts without a
    Lantern. Knobs: `GameConfig.DARK_OBSTACLE_SPACING`, `DARK_DESCENT_SPEED`.
  - `EconomyTest` (core): a good player's career (`Career`) must reach the Midnight Trench in
    ~25 casts, the Abyss in ~150 and a full rope in ~260. Knobs: `RopeStat.COST_CURVE`,
    `GameConfig.TACKLE_PRICE_BY_LENGTH_LEVEL`, `Milestones.all`.
  - Tackle (`Tackle`): the Lantern and the Rare fish detector change only what the player sees,
    so they're allowed in battles (`usableInBattles`; casts report `lanternUsed`/`detectorUsed`
    and secrets that need the dark check `CastResult.sightAided`). The Lucky charm and the
    Sparkle lure change the rules or the water: solo only, so online rules (4 bumps) never
    change; secrets read the cast's own `touchLimit`.
  - The season's free track (`Seasons.rewards`) is player income: `Career` claims it (about three
    casts a day), so re-run `EconomyTest` when changing season XP or rewards.
  - Wagers are against the computer only; winnings go to the balance, not `pointsEarned`.
- **Shop** (`core/.../Shop.kt`, UI in `ui/shop/`; themes are on the Style page and in the Themes
  screen): every item has a euro price and a points
  price (`ShopCatalog.pointsPrice`: minutes of fishing per euro × `POINTS_PER_MINUTE_BY_LENGTH_LEVEL`,
  `MINUTES_PER_EURO` = 45, Lantern packs `LANTERN_MINUTES_PER_EURO` = 60, `tierBonus` for €4.99 and
  €9.99). Never sell for euros anything points can't buy. Prices: mostly €0.50 to €2, sets €2.99,
  a few at €4.99, specials at €9.99 (`ShopTest`). Bundles must be cheaper than their pieces: their
  badge is the computed saving (`discountPercent`). Item ids are store product ids: release builds
  use Google Play (`billing/PlayStore`), debug builds and tests the in-app `TestStore` (approve,
  cancel, fail, pending). Purchases are granted once per token. Seasonal items and passes live in
  `Seasons.kt`, showcase items in `Showcase.kt`; new kinds of grant go through `Grant.Feature`.
  Bump the tour when the shop changes (`TourContentTest` checks every Shop page with items).
- **Accounts** (`PlayerId`, `online/AccountApi.kt`, server `Accounts.kt`): a public id plus a
  secret (the recovery code); the server keeps a hash and one JSON file per player. Gifts (to
  online opponents, `AccountApi.isGiftable`: looks and tackle packs, never passes) are paid in the
  app (euros as `gift_<id>` consumables, or points refunded on failure) and acknowledged after
  they're granted. Cloud save is a Club perk.
- **Sound, haptics and juice** (`app/.../audio/`, `app/.../feel/`): game moments go through
  `feel/FeelMap` (pure, unit tested) to sounds, a haptic and render-only effects, and `GameFeel`
  (what the view model delegates to) applies them with the player's settings. New sounds go in the
  `Sfx` table (with pitch/volume variation, voice limit and minimum gap; no random pitch on tuned
  sounds) and new feel numbers in `GameConfig.Feel`.
  - **Audio is CC0 only.** Every file in `assets/audio` needs its source page, author, pack and
    licence in `assets/audio/CREDITS.md` and `audio/AudioCredits.kt` (shown in Settings >
    Credits); `AudioAssetsTest` fails otherwise. Keep the audio small (under 3 MB): mono OGG
    effects, music loops made seamless at conversion.
  - **Effects are render-only**: shake moves the drawing (2D translate with bleed, 3D projection
    offset and `uHookScreen`), never the hook, fish, steering or hit detection; particles and
    flashes are drawn before the darkness in both renderers. Slow motion only in solo casts
    (`GameFeel.simDt(solo = ...)`): battles and online casts must run in real time.
  - **Reduce motion** turns off shake, slow motion and flashes; haptics respect the Vibration
    setting and stay sparse (no haptics on ordinary taps). Device settings (volumes, haptics,
    reduce motion) live in the key-value store, not in `PlayerProgress`.
  - Robolectric uses `NoAudio`; tests inject fakes through `AudioEngines.factory` and
    `Haptics.factory`. Put each such UI test in its own class: a class's later tests get a view
    model built with the first test's application, so saved settings would live elsewhere.
- All tunable numbers live in `core/.../GameConfig.kt` (plus the tables in `FishSpecies.kt`,
  `Upgrades.kt` and `Secrets.kt`). The tour and HUD read them, so don't hard-code them in UI text.
- Run `./gradlew :core:test :server:test :app:testDebugUnitTest` before pushing. App UI tests
  need JDK 21 (Robolectric emulating Android 16).

## Compose pitfalls already hit in this codebase

- Never call `drawText(textMeasurer, text, topLeft)` near the canvas edge: it throws when the
  text starts below the bottom edge. Use `drawLabel` in `CastRenderer.kt` (measure, then draw).
  `RenderFuzzTest` draws every frame of whole casts to catch render crashes.
- `CastSession` and `Battle` are mutable, non-observable objects. Don't pass them to child
  composables and expect them to refresh: Compose skips the child when the same instance is passed.
  Copy what's shown into plain data first (see `HudState`, `BattleView`). Unused parameters
  are also ignored for skipping.
- The UI tests only draw the game canvas when taking a screenshot, so rendering bugs need
  `RenderFuzzTest`, not the screenshot tests.
